# @ama-styling/mcp Server Setup

Configure the [`@ama-styling/mcp`](https://github.com/AmadeusITGroup/otter/tree/main/mcps/@ama-styling/mcp) server so AI assistants can discover, list, and recommend design tokens from your project's token library instead of guessing or hardcoding values.

## Prerequisites

- A `styling.metadata.json` file generated by `@ama-styling/style-dictionary` using the `ama/json/metadata` format.
- Node.js (LTS recommended) for running `npx`.

## Generating the Metadata File

The MCP server reads a `styling.metadata.json` that contains all your design tokens with their metadata, values, and Otter extensions. To generate it:

1. **Install Style Dictionary with Ama transforms:**

   ```bash
   npm install --save-dev @ama-styling/style-dictionary
   ```

2. **Add the `ama/json/metadata` format** to your Style Dictionary config (`sd.config.js` or `style-dictionary.config.json`):

   ```js
   export default {
     source: ['tokens/**/*.json'],
     platforms: {
       metadata: {
         transformGroup: 'ama/css',
         buildPath: './',
         files: [{
           destination: 'styling.metadata.json',
           format: 'ama/json/metadata'
         }]
       }
     }
   };
   ```

3. **Build the tokens:**

   ```bash
   npx style-dictionary build
   ```

   This produces `styling.metadata.json` at the project root.

## Configuration

The server runs via `npx` with no permanent install required.

### Claude Code

Add to `.mcp.json` at the project root:

```json
{
  "mcpServers": {
    "ama-styling": {
      "command": "npx",
      "args": ["-y", "-p", "@ama-styling/mcp", "ama-styling-mcp-start", "--metadata", "./styling.metadata.json"]
    }
  }
}
```

### GitHub Copilot (VS Code)

Add to `.vscode/mcp.json`:

```json
{
  "servers": {
    "ama-styling": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "-p", "@ama-styling/mcp", "ama-styling-mcp-start", "--metadata", "./styling.metadata.json"]
    }
  }
}
```

## CLI Options

| Option | Description | Default |
|--------|-------------|---------|
| `--metadata <path>` | Path to `styling.metadata.json` | `./styling.metadata.json` |
| `--log-level <level>` | Log verbosity (`debug`, `info`, `warn`, `error`) | `info` |

Example with custom path and debug logging:

```json
{
  "mcpServers": {
    "ama-styling": {
      "command": "npx",
      "args": ["-y", "-p", "@ama-styling/mcp", "ama-styling-mcp-start", "--metadata", "./design-system/tokens.metadata.json", "--log-level", "debug"]
    }
  }
}
```

## Metrics (Optional)

Ask the user whether to enable anonymous usage metrics. If they agree, add an `env` block to the server config:

```json
"env": {
  "O3R_METRICS": "true"
}
```

Privacy policy: https://github.com/AmadeusITGroup/otter/blob/main/PRIVACY.md

## Verification

After configuration, restart your AI assistant and verify the MCP is active:

- **Claude Code:** The `find_design_token` and `list_design_tokens` tools should be available.
- **VS Code Copilot:** The server should appear in the MCP panel and respond to token queries.

If the tools are not available, check:
1. The `styling.metadata.json` file exists at the specified path
2. Node.js is accessible from the assistant's environment
3. The `@ama-styling/mcp` package can be downloaded (network access)
