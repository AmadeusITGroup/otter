# Minor 15.2 Migration guide

> [!IMPORTANT]
> Please make sure to first follow the ["Upgrade new version guide"](https://github.com/AmadeusITGroup/otter/blob/main/docs/core/UPGRADE_NEW_VERSION.md) before going through these steps.

> [!NOTE]
> An agent-oriented version of this guide is available in [15.2.agent.md](./15.2.agent.md).

## Renovate — `generatorDependencies` are now updated by an Otter preset

The Otter `base` Renovate preset now keeps the `generatorDependencies` block of your `package.json` files up-to-date.
Renovate's built-in `npm` manager ignores that block, so its versions used to go stale.
That in turn failed the [`@o3r/json-dependency-versions-harmonize`](../docs/linter/eslint-plugin/rules/json-dependency-versions-harmonize.md) lint rule, which does check it.

There is nothing to do if you already extend the Otter `base` preset, as the new manager comes with it.
Two cases still need a manual change.

### 1. You already had your own `generatorDependencies` custom manager

Remove it, otherwise the same dependency is picked up twice and you get duplicated branches and pull requests for a single version bump.

Look for a `customManagers` entry (or the deprecated `regexManagers`) mentioning `generatorDependencies` in your Renovate configuration and delete it.
The configuration is usually one of `renovate.json`, `renovate.json5`, `.renovaterc`, `.renovaterc.json`, `.github/renovate.json5` or `.gitlab/renovate.json5`.

If your manager did something extra, such as a different `versioningTemplate` or a narrower `fileMatch`, keep only that part and express it as a rule on the `depType` set by the Otter preset:

```json5
{
  "packageRules": [
    {
      "matchDepTypes": ["generatorDependencies"],
      "groupName": "Otter generator dependencies"
    }
  ]
}
```

### 2. You restrict `enabledManagers`

Add `custom.regex` to the list:

```json5
{
  "enabledManagers": [
    "npm",
    "github-actions",
    "custom.regex"
  ]
}
```

`enabledManagers` is an allow-list: when it is set, Renovate runs only the managers you list.
The new preset is a [custom regex manager](https://docs.renovatebot.com/modules/manager/regex/), so without `custom.regex` it is silently skipped.
The other Otter manager presets (`github-node-version`, `mcp-servers`, `renovate-otter-presets`) are skipped for the same reason.

If you do not define `enabledManagers` at all, there is nothing to do, as every manager is enabled by default.
